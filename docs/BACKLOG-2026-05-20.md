### 5. Address GraphQL auth/ACL stubs (security gap)

`internal/graphql/resolver/schema.resolvers.go` contains **11 TODO items** for missing
auth/ACL enforcement in GraphQL mutations and queries. Unlike the REST handlers (which
go through Fiber middleware), GraphQL mutations currently bypass authentication entirely:

```go
// line 337 — TODO: Add authentication check when auth middleware is implemented
// line 340 — TODO: Add ACL check when ACL middleware is implemented
// line 357 — (repeated pattern across all write mutations)
```

`internal/handlers/auth.go:60` has a related gap:
```go
// TODO: Add actual password validation against a user store
```

This is a **security risk for any deployment that exposes the GraphQL endpoint**.
`internal/graphql/resolver/authz.go` already has `claimsFromGraphQLContext()` and
`authorizeMutation()` — wire them into the resolver methods instead of leaving stubs.

Priority: if the `/graphql` route is protected by REST middleware globally, this may
be lower risk; confirm and document whether the middleware chain covers GraphQL before
deferring.
