## P1 — High Priority (this week, after PR lands)

### 3. Wire `RBACCacheHitRatio` metric

`metrics.go` declares `RBACCacheHitRatio` (Gauge) but `manager.go` never calls
`.Set()` on it. The metric always reports 0, which is misleading.

**Fix** — add atomic counters to `Manager` and update ratio on each cache access:

```go
// in Manager struct:
cacheHits   atomic.Int64
cacheMisses atomic.Int64

// in GetEffectivePolicies, fast-path branch:
m.cacheHits.Add(1)
total := m.cacheHits.Load() + m.cacheMisses.Load()
if total > 0 {
    RBACCacheHitRatio.Set(float64(m.cacheHits.Load()) / float64(total))
}

// in the slow path (cache miss):
m.cacheMisses.Add(1)
```

**File**: `internal/rbac/manager.go:105`

### 6. RBAC persistence — survive restarts

Current `MemoryRoleStore` and `MemoryAssignmentStore` are in-memory only.
Roles and assignments are lost on restart. Options:
- **Short term**: serialize to BadgerDB on write (similar to KV store)
- **Long term**: replicate via Raft so all nodes share RBAC state

Add a `BadgerRoleStore` / `BadgerAssignmentStore` analogous to
`internal/persistence/`.

**Est**: 1–2 days
